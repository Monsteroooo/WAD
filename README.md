Варіант 8: Вікторина зі збереженням результатів

## 1. Пошук innerHTML
Пошуком по проєкту знайдено одне місце з innerHTML — у функції decodeHTML у файлі js/app.js. Вона створює елемент textarea для декодування спецсимволів HTML (наприклад, &quot;, &#039;), які приходять з API або локального файлу з питаннями. Сама по собі ця функція безпечна, бо елемент textarea створюється в пам'яті й не додається в DOM сторінки, а його вміст розбирається як текст, тому скрипти там не виконуються.
Усі інші елементи інтерфейсу рендеряться через React (JSX), який за замовчуванням вставляє текст через textContent, тому dangerouslySetInnerHTML або звичайний innerHTML у компонентах не використовується.

## 2. Підтвердження вразливості (XSS)
Для перевірки вразливості у перше питання в server/data/questions.json було додано тестовий рядок:
<img src=x onerror="alert('XSS')">

Коли в компоненті QuizQuestion було змодельовано пряму вставку HTML через dangerouslySetInnerHTML (аналог innerHTML у чистому DOM), браузер спробував завантажити картинку з адреси /x, отримав 404 помилку і викликав подію onerror, через що на екрані з'явився alert('XSS'). Це підтвердило наявність XSS-вразливості до виправлення.

## 3. Виправлення вразливості
Вразливе місце було виправлено:
1. У компоненті QuizQuestion текст питання виводиться як звичайний текст: `<p id="question-text">{question}</p>`, що працює аналогічно textContent і безпечно екранує всі HTML-теги.
2. У js/app.js також додано функцію escapeHTML, яка замінює символи &, <, >, ", ' на відповідні HTML-сутності.

Після оновлення сторінки тестовий рядок з тегом img виводиться на екран звичайним текстом, а скрипт більше не запускається.

## 4. Перевірка даних у localStorage та IndexedDB
У DevTools (вкладка Application) перевірено дані у localStorage та базі даних QuizDB (сховище results).
Зберігаються лише результати спроб з полями: id, date, score, total, а також службовий ключ міграції.
Жодної чутливої інформації (паролі, токени авторизації, персональні дані) там немає. Відповідно до варіанту 8, ці дані є звичайною статистикою вікторини і не є чутливими.

## 5. Перевірка на наявність секретів
У коді немає захардкоджених паролів, приватних ключів чи платних API-токенів. Зовнішній API Open Trivia DB публічний і не вимагає авторизації, а локальний сервер не потребує секретів. У файл .gitignore додано шаблони для .env файлів, щоб уникнути випадкового потрапляння змінних середовища в репозиторій.

## 6. Налаштування HTTPS
Для публікації застосунку обрано GitHub Pages. Там HTTPS підтримується за замовчуванням через налаштування Enforce HTTPS.
